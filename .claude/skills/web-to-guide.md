# 웹 페이지 → 우리 팀 가이드 문서 변환 스킬

`$ARGUMENTS`에서 URL과 파일명(선택)을 파싱한다.
- 첫 번째 인자: 변환할 웹 페이지 URL (필수)
- 두 번째 인자: 출력 파일명 (선택, 없으면 페이지 제목 기반 kebab-case)

## 작업 순서

### 1단계: URL에서 콘텐츠 추출
- `$ARGUMENTS`의 URL을 WebFetch로 페이지 전체 내용을 마크다운 형식으로 추출
- 제목, 소제목, 본문, 단계별 설명, 주의사항 등 모든 내용을 원문 그대로 유지

### 2단계: 콘텐츠 정제 (중요)
원본 사이트의 다음 항목들을 **반드시 제거**:
- 해당 사이트 자체 서비스 홍보, 광고 문구
- 문의처, 고객센터, 상담 안내 링크
- 도움말, FAQ, 관련 매뉴얼 등 외부 링크
- 사이트 내부 네비게이션, 푸터 정보
- "저희 서비스로 대행 가능" 등 해당 사이트 서비스 유도 문구
- 출처 사이트에 종속된 내용 (예: 특정 플랫폼 전용 조건, 가격 등)

**유지해야 할 것**: 구글, 애플 등 공식 플랫폼의 정책/절차/주의사항 등 범용적인 가이드 내용

### 3단계: 이미지 URL 추출
- WebFetch로 페이지 내 모든 이미지 URL을 추출
- 각 이미지가 어떤 섹션/단계에 해당하는지 매핑

### 4단계: 이미지 다운로드
- `images/{가이드명}/` 하위 폴더를 생성하여 이미지 관리
  - 예: `images/google-business-developer/step1_01_account_type.png`
- curl로 모든 이미지를 다운로드
- 파일명은 `step{N}_{순번}_{설명}.png` 형식 (예: `step1_01_account_type.png`)
- 다운로드 후 파일 크기 확인하여 정상 여부 검증

### 5단계: 마크다운 문서 작성
- 정제된 콘텐츠를 구조화된 마크다운으로 작성
- 각 단계별 설명 아래에 `![설명](images/{가이드명}/파일명.png)` 형태로 이미지 삽입
- 중요 주의사항은 `> **주의**:` 블록인용 또는 표로 강조
- 파일은 프로젝트 루트에 저장

## 출력 파일명 규칙
- 인자로 파일명이 주어지면 해당 이름 사용
- 없으면 페이지 제목 기반으로 kebab-case `.md` 파일 생성
- 이미지 폴더명도 동일한 kebab-case 이름 사용

## 주의사항
- 이미지 다운로드 시 `?alt=media` 파라미터가 필요한 경우 자동 추가 (gitbook 등)
- 원본 텍스트의 언어(한국어 등)를 변경하지 않음
- 출처 사이트명이나 URL을 문서 본문에 남기지 않음
